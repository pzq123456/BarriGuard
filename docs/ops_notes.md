# 运维说明（告警行为白名单，给一线/客户看）

以下行为是设计如此，不是故障，接到这类“报障”先对照本页：

1. **车走了框还在（拖尾几十秒）**：遮挡离开后，异常累计按 `decay_rate` 衰减，
RER 还有 2 次迟滞确认，框会再跟几十秒才消失（`intact_reset_s=5` 是连续
5 秒“干净”才秒脱锁，半干净就慢慢衰）。不是卡死。
2. **画面压着 SUNGLARE 黄字**：表示路面反光太强、颜色逻辑不可信，
此时“无报警”= 不知道，不是确认正常。报警照样会报（状态只定级不拦检测）。
3. **报警框里是车/人**：静态 PER 帧确实分不清遮挡和真缺口，靠时间区分——
车走框消；**停着不动的车超 hold 时间必报**，只能人工看框（车/路一眼可辨），
系统不背这个锅（见 tuning brief 问题 2）。
4. **持续报警只偶尔存图**：上升沿存 1 张，之后每 `evidence_resave_s`（默认 300s）
补 1 张。不是漏存，是防刷盘。
5. **`/events/{id}` 有 `status` 字段**：OK / SUNGLARE，转发/复核看这个，
不要只看有没有 events。
