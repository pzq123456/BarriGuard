## 1. 结论摘要

- 全视频自动检测出 **1 盏确认熄灭的警示灯**：远处护栏线 **(1305.2, 411.9)**。
  - 证据：静态灯罩占空比 0.89（灯罩几何在位），30 分钟逐窗 duty 全部 ≤2%，事件率 0.6-1.2% 且无周期性（ac=0.03）；
  - 邻居对照：左 (1264.4,421.3) duty 29.4%/lag7/ac0.95，右 (1326.5,411.6) duty 25.4%/lag6/ac0.46 均正常闪烁。
  - 定位：远线上从左数第 3 盏（链条 1227 → 1264 → **1305(灭)** → 1326 → 1382 → …）。
- 已知残差 FP 1 处：(839.8, 498.7) —— 大门口全程站立的工人黄色安全帽（静态琥珀色），属场景语义问题，需人形/门区屏蔽解决。
- 近处左护栏线 4 盏常亮琥珀灯全部在位点亮；右侧近景护栏为空杆（无灯，不可验证）。

| 区域 | 内容 | 光特征 |
|---|---|---|

| 远护栏线 (x≈1220-1830, y≈380-445) | **同步闪烁**灯串，周期 ~7 帧 (0.56s)，duty 19-52% | 多数核心白热（低 S）+ 琥珀边缘，纯琥珀模型会漏检 |
| 右侧近景护栏 | 反光条 + 空杆，**无灯** | 白/红反光，随车辆灯光闪变（周期性假象源） |
| 背景 | 上方远处道路灯、左上远处灯光串、OSD 4G 信号条（动画）、大门行人 | 各类周期/静态假象源 |

关键场景事实：
- 水马表面**高频纹理**：相邻像素灰度差可达 ±40-90 —— 背景模型必须逐像素。
- 白色水马 V≥235&S≤90、红色塑料 H0-8、绿色防护网 H70-106（y≈391 处网顶反光会形成假轨迹）。
- 灯罩（未点亮/点亮均可）呈琥珀色壳体，是"熄灭灯"唯一可见痕迹：dome H12-32, S60-175, V70-190。
- 帧 ~16200-18000（约 01:24-01:30）出现曝光泵动/雨雾事件，闪光 spot 数从 ~360 暴增到 ~1000，需窗口级稳定性过滤。

## 3. 方法演进与教训（3 代迭代）

### v1 `night_lamp_detector.py`：琥珀亮斑轨迹 + 静态灯罩
- 产出 52 活灯 / 13 死灯候选，人工 montage 核验 13 个候选全部为 FP（路灯、标牌、绿网、灌木、锥桶、人帽、反光）。
- **教训 1**：纯琥珀"发光"模型对**白热闪光灯**有盲区 —— (1595,396) 被误判死灯，实际是 duty 19%/lag8/ac0.84 的活灯。→ 发光检测必须颜色无关。

### v2 `lamp_pipeline.py`：逐窗 p50 背景 + 固定 ROI 序列
- 逐像素 p50 背景差分 + max 图闪光检测，方向正确；但 spot 合并（盒式取第一个命中）导致：
  - L1383 与邻斑 (1394,429) 合并丢轨迹 → 产生假死灯 (1382,433)；
  - 反光斑 G1308(1308,399) 抑制了真死灯 D1305（距离 20.8px，阈值 14px 内被吞）；
  - 常亮灯正下方地面反光 (101,619)(111,615)(709,508) 成为死灯候选（缺"灯下反射"规则）。

### v3 中间失败（重要工程教训）
- **块状背景失败**：16x16 块 p50 在高对比静边缘（水马顶沿）产生 912 个假 spot（边缘渗色）。→ 必须逐像素背景。
- **半分辨率背景失败**：`gray[::2,::2]` 采样 + 最近邻上采样，使未采样像素使用 1-2px 外邻居的 p50；水马纹理像素间差 ±40-90 → 每帧恒有 ~11-15 个纹理噪声像素超过 +60 阈值 → duty=100%，全线误判。**实测 OFF 帧 ROI 内假"闪光"=11px，与理论完全吻合。** → 背景必须全分辨率逐像素。
- **窗口采样数奇偶 bug**：`win_frames=int(180*fps)=2247` 为奇数 → 窗口起点帧奇偶交替 → 采样数 1124/1123 交替，`len(pat)==win_samples` 硬判等把**一半窗口的序列静默丢弃**（ser_n=5 而非 8-9）。→ `win_frames` 取偶。

### v3 最终算法（`night_lamp/experiments/night_lamp_pipeline.py`）
单遍扫描，3min 窗口，stride=2：
1. 每窗口全分辨率 **16 平面 uint16 灰度直方图** → 逐像素 p50 背景（`k*16+8`）；
2. 全窗口逐像素 max → `flash = max - bg` → 阈值 60 → 连通域(minA=6) → **最近邻匹配**(欧氏 ≤10px) 进 spot 表；位置 EMA 平滑；
3. 已知 spot 在窗口起点固定 20x20 ROI 缓存 patch，窗口末用**同一坐标**的 bg 切片生成逐样本闪光计数序列（消除 ROI/bg 错位）；
4. 分类：
   - **ALIVE-FLASH**: duty∈[5%,85%]、自相关 lag∈[5,12] 且 ac≥0.35、亮窗占比≥60%（窗口级 duty≥3%）；
   - **ALIVE-STEADY**: 琥珀静态高亮 (H12-28,S≥140,V≥185 占比≥0.80)；
   - **DEAD**: 静态灯罩 (H12-32,S60-175,V70-190 占比≥0.60、area 3-60、fill≥0.45、aspect 0.4-2.5、带内、y<1065) 且 **18px(dy≤12)内无 ALIVE** 且 **非常亮灯正下方 ≤55px 的反射**(dx≤25, dy∈[-55,-5])。
- 最终结果：358 个含序列 spot → 89 ALIVE-FLASH、6 STEADY blob(=4 盏)、**2 DEAD**（真死灯 + 人帽 FP）。

## 7. 局限与工程化建议

1. **夜间水马分割不可靠**（`server/barrier.process`）：远线灯罩相对夜间顶沿 -8~-159px，几何先验不可用 → 用"带 (band) + 灯链聚类"替代。
2. 单视角：被前排水马/行人遮挡的灯不可见；右侧线无灯无法验证 → 部署时需多机位或标定遮挡区。
3. 参数相机相关：fps=12.49（lag 窗口 [5,12] 按 0.56s 周期设定）、FLASH_TH=60、duty 域随曝光策略漂移 → 部署时按相机标定，或自适应估计周期。
4. 性能：单遍 ~600s/30min 视频（CPU）；工程化可降采样至 stride=3、ROI 限定带内，预计 <3min。
5. 建议上线形态：本 v3 作为"离线巡检"批处理；在线模式用滑动 3min 窗 + 相同分类器，输出带置信度的死灯列表 + 沿链序号。
   （本条已取代：生产采用 40 帧突发抽查 ＋ night gate，v3 分类器未进生产，见 §9。）
